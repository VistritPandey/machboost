# MachBoost 0.16.1

This hotfix repairs multi-turn Claude Desktop inference and keeps team-hosted
models resident between sessions.

## Fixed

- Accepts Anthropic `thinking` and `redacted_thinking` history blocks instead
  of returning HTTP 400 after a reasoning or tool-use turn.
- Excludes private reasoning blocks from the model's replayed conversation
  context.
- Keeps the Anthropic tool prefix stable across follow-up turns so the native
  MLX-VLM prompt cache remains reusable.
- Assigns authenticated API clients a native VLM cache affinity automatically.
- Keeps models loaded indefinitely by default when MachBoost runs in team mode.
  Explicit unload and per-request keep-alive values still take precedence.

## Measured Claude Latency

On the same loaded `mlx-community/Muse-Glimmer-30B-4bit` model, a controlled
Claude-shaped workload used a 7,825-token prompt, 64 advertised tools, reasoning,
and 32 generated tokens. The first uncached request measured 64.83 seconds to
first token. Before this fix, growing follow-ups measured about 34 seconds because
their changing tool prefix invalidated the cache. With this fix, the measured
follow-ups were 1.29 and 2.17 seconds; an exact repeat measured 0.63 seconds.

The first request after a model load or a genuinely new large prefix still has
to perform prompt ingestion. This release improves resident, repeated Claude
work rather than claiming that every cold prompt is instant.
