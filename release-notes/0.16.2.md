# MachBoost 0.16.2

This release reduces cold Claude and coding-agent latency for native MLX-VLM
models while making startup costs easier to diagnose.

## Improved

- Persists MLX-VLM automatic prefix-cache blocks to a bounded local SSD cache,
  allowing stable system, tool, and repository prefixes to survive app or
  daemon restarts.
- Scopes persistent entries by model revision and request affinity to prevent
  stale-weight reuse and cross-client cache collisions.
- Compile-warms native vision-language models when a model is explicitly
  loaded with warm-up enabled.
- Reduces the default Anthropic tool-schema budget from 48 to 24, retaining
  core coding tools, previously used tools, and tools relevant to the initial
  request. `MACHBOOST_ANTHROPIC_TOOL_LIMIT` remains available as an override.
- Reports model load, prompt evaluation, generation, and total durations
  separately in OpenAI-compatible MachBoost metadata.

## Measured Muse Restart Latency

A controlled test used `mlx-community/Muse-Glimmer-30B-4bit`, 24 verbose coding
tools, a 3,448-token prompt, and one generated token. The cold process measured
30.04 seconds to first token. A second fresh process restored 3,432 prefix
tokens from the persistent cache and measured 1.79 seconds to first token.
Including model load in both runs, total wall time changed from 34.66 seconds to
6.03 seconds, a 5.75x reduction.

This result applies to a previously seen stable prefix after restart. A truly
new prompt prefix still requires model prefill, and output decoding is not
cached. The persistent cache is local, bounded to 8 GiB by default, and can be
disabled with `MACHBOOST_MLX_APC_DISK=0`.
