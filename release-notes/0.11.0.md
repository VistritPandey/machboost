# MachBoost 0.11.0

MachBoost 0.11.0 adds a supported bridge for Meta Muse Glimmer 30B MLX across
the CLI, resident server, Python client, and native macOS app. It also adds a
same-engine benchmark contract that separates model-native DFlash performance
from MachBoost gateway overhead.

## Muse Glimmer 30B MLX

- `muse-glimmer:30b-mlx` is available through `pull`, `run`, `chat`, `complete`,
  `warm`, `list`, model lifecycle routes, and both chat API families.
- Text, image input, reasoning strengths, native function-tool output,
  streaming, request IDs, cancellation, and keep-alive are preserved through
  Ollama's MLX runner.
- The native app exposes model capabilities, reasoning controls, separate
  reasoning display, structured tool-call display, context metadata, and an
  explicit approximately 21 GB download confirmation.
- MachBoost finds both command-line Ollama installations and
  `/Applications/Ollama.app`, including Finder-only installations whose CLI is
  not present in `PATH`.
- Muse Glimmer requires Apple Silicon, Ollama 0.32.7 or newer, and a
  conservative minimum of 32 GB unified memory. Ollama is not bundled or
  modified by MachBoost.

The native app displays and exports tool calls but does not execute arbitrary
tools. Connected agents remain responsible for tool authorization and
execution.

## Measured Behavior

On an Apple M5 Pro with 48 GB unified memory, five measured 256-token rounds
after two warmups produced:

| Mode | Direct Ollama | MachBoost | Gateway overhead |
|---|---:|---:|---:|
| Native DFlash | 22.50 tok/s | 21.61 tok/s | 4.11% |
| No-spec diagnostic | 17.28 tok/s | 17.29 tok/s | 0.02% |

The MachBoost DFlash leg reached 1.25x the diagnostic control's decode
throughput and 1.27x its wall-time performance. Direct Ollama reached 1.30x and
1.32x, respectively.

The control requests token logprobs because Ollama's public MLX API does not
provide a direct DFlash-off switch. Logprob materialization is therefore part
of the baseline cost. This is not directly comparable to Meta's runtime-level
ExecuTorch measurements, and only 2/10 same-prompt pairs were byte-identical.
No exact-output or universal quality-equivalence claim is made. Full methods,
feature smokes, concurrency behavior, and caveats are stored in
`results/muse_glimmer_30b_mlx_20260811.json`.

## Serving And Reliability

- Indefinite MachBoost residency now maps to Ollama's supported negative
  duration instead of sending the rejected string `forever`.
- Null optional Ollama settings are treated as omitted, fixing interactive CLI
  and app requests that do not set `num_ctx` or advanced visual controls.
- Same-engine benchmarks isolate direct and gateway prompt-cache state with
  engine-specific nonces and label output comparison as not applicable.
- `--draft-num-predict 0` is explicitly described as a logprobs-based
  diagnostic control rather than a pure no-speculation baseline.
- Benchmark JSON now records platform, architecture, and Python version.

## Install

```sh
python3 -m pip install --upgrade machboost
machboost pull muse-glimmer:30b-mlx
machboost run muse-glimmer:30b-mlx --think high --show-thinking --show-stats
```

The unsigned community macOS build can be packaged with:

```sh
./scripts/release_macos.sh 0.11.0-local --local
```
