# MachBoost 0.16.10

This hotfix prevents development builds from taking over the installed macOS
app's local server and incorrectly reporting native MLX models as unsupported.

## Changes

- Requires the production app to use its own bundled, pinned Python and MLX
  runtime instead of reusing an unrelated process on the same port.
- Gracefully replaces a healthy same-version development or global-Python
  daemon before starting the bundled runtime.
- Terminates each Xcode UI-test app after its test, preventing a Debug build
  from surviving the suite and intercepting later app launches.
- Separates `Runtime unavailable` from `Architecture unsupported` in the model
  browser so installation failures are not presented as model incompatibility.
- Keeps model capabilities independent: chat, completion, vision, reasoning,
  and tools are shown only when model metadata supports them.

Plain text and source files remain available to chat models through workspace
context. Images require a vision-capable model. This release does not claim
native audio inference support.

## Validation

- 72 Swift unit tests pass.
- 20 native macOS UI tests pass, with no surviving test app after teardown.
- The installed app was verified to launch its bundled CPython runtime with
  MLX, MLX-LM, MLX-VLM, and DFlash available.
- The live catalog reports Llama 3.2 text, Gemma 4 vision/reasoning, and Muse
  Glimmer vision/reasoning/tool models as ready on the development Mac.
